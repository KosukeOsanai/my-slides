## 5. Blacksmithとは（0:36）

- 「Blacksmith は、GitHub Actions の Job を動かすマシン、つまり Runner を提供するサービスです」
- 「GitHub が用意する Runner の代わりです。サーバーは自分で持ちません」
- 「コスト削減と速度向上を狙うサービスです」

## 6. GitHub Actionsのrunnerとは（0:48）

- 「Runner は、ワークフローのジョブを実行する環境です」
- 「GitHub 公式が管理する GitHub-hosted runner と、自分でマシンを用意する self-hosted runner があります」
- 「Blacksmith は、公式 Runner の代わりに使う側です」

## 7. CIを安くするアプローチ（1:00）

- 「CIのコストは、だいたい 単価 × 実行時間 です」
- 「安くするアプローチは2つ。単価を下げることと、実行時間を縮めることです」
- 「Blacksmith は、この両方を取りにいく、というサービスです。数字は次の2枚で、公式の主張です」

## 8. 1. 単価が安くなる（1:16）

- 「GitHub の Linux 2-core は1分 $0.006 です」
- 「Blacksmith の Ubuntu x64 は1分 $0.004。公式は、GitHub の分単価より 33% 安い、と言っています」
- 「$0.004 は $0.006 のちょうど3分の2です」

## 9. 2. 性能が上がる（1:34）

- 「もう一つは性能です。公式は、GitHub の Runner より2倍速いハードウェア、キャッシュのダウンロードは4倍速い、と言っています」
- 「実行時間が半分になれば、単価が33%安いことと合わせて、最大67%安くなる、という計算です」
- 「67%は、2倍速くなる前提の公式の試算です。保証ではありません」

## 12. プロダクトA / Bでは効いた（2:26）

- 「効いたのは2つです。どちらも同じ 2vCPU で、成功 run の中央値です」
- 「プロダクトAのテストは、9.7分から 3.9分、1回が $0.192 から $0.056 です」
- 「プロダクトBは、テストと静的解析を合わせると 10.7分から 5.8分、1回が $0.108 から $0.044 です」
- 「2行を単純平均すると、実行時間は約53%、コストは約65%の削減です。どちらも採用しました」
- 聞かれたら: 平均は run 数で重み付けしていない。Aのコストだけなら約71%、Aの実行時間だけなら約60%。金額はジョブを1分に切り上げた推定で、請求書の実額ではない。Bの内訳はテスト 7.5分→4.0分（$0.048→$0.020）、静的解析 3.2分→1.8分（$0.060→$0.024）。静的解析は Larastan / PHPMD / Deptrac で、最長は Larastan

## 13. プロダクトCでは効かなかった（2:58）

- 「プロダクトCは同じ入れ方で見送りました」
- 「テスト本体は 38秒から 15秒と速いです。でも setup-php が 10秒から 78秒になって、ジョブ全体は 69秒から 103秒です」
- 「pest・phpstan・phparkitect の3ジョブで、コストは $0.024 のままです。単価は安いのに、分が増えて相殺されました」
- 4vCPU も測っている。待ちは88秒、コストは $0.048 で悪化。時間があれば一文。無ければ言わない

## 14. なぜ setup-php だけ遅くなる？（3:30）

- 「setup-php の作者が、Issue #1056 で理由を書いています」
- 「GitHub-hosted は、最初から入っているライブラリが分かっているので、ビルド済みのキャッシュを展開するだけで終わります」
- 「self-hosted runner だと、その前提がないので、足りないライブラリを apt でその場で入れます。そこで時間がかかります」
- 「速いマシンに載せても、Action の動きが変わると、全体は遅くなり得ます。Blacksmith 固有、とは断定しません」

## 15. 結果はプロダクトで割れた（3:52）

- 「プロダクトAとBは実行時間が縮んでコストも減ったので採用。プロダクトCは本体は速いのに setup-php で全体が悪化し、コストも下がらなかったので見送りです」
- 「最初の式に戻ります。単価が安くても、実行時間が伸びればコストは下がりません」
- 「戻すときは、runs-on を GitHub Actions のものに戻せばよいです」
