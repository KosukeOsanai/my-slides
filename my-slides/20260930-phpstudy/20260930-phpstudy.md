# Blacksmithとは

* Blacksmith Software社が提供するGitHub Actionsの代替runner
  * https://www.blacksmith.sh/
* CIのコスト削減、速度向上に寄与する

---

# GitHub Actionsのrunnerとは

* GitHub Actionsワークフローでジョブを実行する環境
  * GitHub公式が管理・提供するGitHub-hosted runner
  * 自分でマシン等を用意するself-hosted runner

---
# CIのコストを下げるには

1. Runnerの単価を下げる
2. 実行時間を縮める

```text
CIのジョブにかかる料金 ≒ Runnerの単価 × 実行時間
```

# 1. 分単価が安くなる

| | 分単価 |

  * https://www.blacksmith.sh/pricing

# 導入手順

1. [app.blacksmith.sh](https://app.blacksmith.sh) で GitHub Organization と連携
2. `runs-on` を Blacksmith の Runner に変える

```yaml
runs-on: ubuntu-latest
```

↓

```yaml
runs-on: blacksmith-2vcpu-ubuntu-2404
```

※制約：GitHub Organizations が必要

---

# プロダクトA / Bでは効いた

成功 run の中央値。どちらも 2vCPU

| | 実行時間 | 1回のコスト |
|---|---|---|
| A  | 9.7分 → **3.9分** | $0.192 → **$0.056** |
| B の テスト | 10.7分 → **5.8分** | $0.108 → **$0.044** |

**実行時間が平均53%、コストが平均65%削減** → **採用**

<!--
待ちは最長ジョブ。コストはジョブごとに切り上げた分 × 単価の推定で、請求書の実額ではない。
AのTestは導入前後各18 run。9.7分は583秒、3.9分は236秒。$0.192は32分×$0.006、$0.056は14分×$0.004。約60%短縮、約71%減。
BのUnit Testはテストを実行したrunだけ（前11、後13）。7.5分=447秒、4.0分=242秒。
Bの静的解析はLarastan / PHPMD / Deptracの待ち。前7、後8。3.2分=194秒、1.8分=106秒。
-->

# プロダクトCでは効かなかった

| | 導入前 | Blacksmith 2vCPU |
|---|---|---|
| テスト本体 | 38秒 | **15秒** |
| setup-php | 10秒 | **78秒** |
| ジョブ全体 | 69秒 | **103秒** |
| 3ジョブのコスト | $0.024 | **$0.024** |

* プロダクトCで利用していたsetup-phpの所要時間が大きく増加。
* テスト本体の速度は向上
* job全体が逆に遅くなったため**採用見送り**

<!--
3ジョブは pest / phpstan / phparkitect。コストは切り上げ分 × 単価。
2vCPU は課金分が4分から6分に増え、単価差と相殺して同額。
4vCPU は待ち88秒・コスト$0.048で、こちらも採用しなかった。スライドでは同じ2vCPU比較だけ話す。
-->

---

# なぜ setup-php だけ遅くなる？

* `shivammathur/setup-php`のself-hosted runnerにおける制約
 * https://github.com/shivammathur/setup-php/issues/1056

* **GitHub-hosted** — 入っているライブラリが既知なので、ビルド済みキャッシュを展開するだけ
* **self-hosted runner** — 不足ライブラリを `apt` で都度入れるので時間がかかる

<!--
作者コメントの要旨だけ。原文の長い引用は読まない。
depot.dev や WarpBuild の横展開は、5分では省く。
「Blacksmith固有、と断定しない。Third-partyだと apt 経路になる」まで。
-->

---

# 最終的なBlacksmithの採用状況

* **プロダクトA / Bは採用**
  * CIの所要時間が縮み、コストも減った
* **プロダクトCは見送り** 
  * テスト本体は速いが setup-php が膨らみ、全体の時間は悪化、コストは横ばい

* **切り戻す際はGHAのruns-onを戻せばよい**

---

# まとめ

1. BlacksmithはCIのスピードアップ、コストダウンにつながる
2. 導入は Organization 連携と、`runs-on` の変更
3. 導入したらCIで実測して判断。切り戻しも`runs-on` 1行の変更
