### 第1弾: AI時代、エンジニアの仕事はどう変わる？（3本）

共通点（記事より）: 「AIの出力をそのまま受け入れず、現場の制約や判断につなげようとしている」

| 切り口 | セッション | 登壇者 |
|---|---|---|
| レガシー改修にAIを活かす | AI駆動で挑む！？レガシーPHPプロダクトのバージョンアップへの軌跡 | ざき（@zaki_yamazaki_zaki）さん |
| AIとチームの仮説検証 | 生成AIを用いてチーム開発する際の７つのポイント　仮説検証のポイントを漫画『瑠璃の宝石』をヒントにして | 小泉岳人さん |
| 生成コードの文脈を引き継ぐ | AIコーディングをセッションで終わらせない：PHPライブラリ開発におけるコンテキスト承継設計 | wakaba（@effy_staffs）さん |

見どころメモ:
- ざき: フレームワークもクラスもない既存プロダクトのバージョンアップ。失敗談あり
- 小泉: 鉱物探しの観察・仮説検証 → AI時代のチーム開発の7つのポイント
- wakaba: 「そうじゃねぇんだよなぁ」となる生成コード。前回の判断や規約を次の作業へ引き継ぐ「コンテキスト承継設計」

## 2. タイプ別モデルルート（本発表のオリジナル提案）

note記事の「こんな方におすすめ」と各セッションの見どころから、人物像ごとに束ね直した。
22セッションすべてがどこかのルートに1回以上入るようにしている。

| ルート | こんな人 | セッション |
|---|---|---|
| A. AIと上手に付き合いたい | AIを使い倒しているが出力の質・学びに不安 | ざき → 小泉 → wakaba → 永瀬 |
| B. 現場の品質を上げたい | 設計・テスト・計測・運用の改善を担う | 梶川 → 河瀨 → 赤間 → ムナカタ → つっつん（メール） |
| C. 言語仕様が好き | 型・静的解析・言語仕様の「なぜ」を知りたい | ムラタ → tadsan → 松尾 → マグロ → 福井 |
| D. 次の一歩を探している | 若手・初参加・コミュニティ/OSSに興味 | meihei → ポチ → あすと. → 河村 → あき |
| E. PHPで越境・遊びたい | Web以外/他言語とのつながりに興味 | ゆずねり → sizuhiko → つっつん（MIDI） |

- 根拠になる記事の記述
  - A: 第1弾「こんな方におすすめ」全般、第3弾 永瀬さん「AIを学習効率を上げるために使えないか」
  - B: 第2弾「LaravelやPHPの設計方針に悩んでいる方」「開発生産性や運用上の問題を改善したい方」
  - C: 第2弾「型・静的解析」、第4弾「PHPの言語仕様や標準関数の挙動に興味がある方」「バージョンアップや互換性」
  - D: 第3弾「初めてカンファレンスへ参加する方や、新しい刺激が欲しい方」「個人開発やOSS貢献、コミュニティへの参加」
  - E: 第4弾「WebPやWasmなど周辺技術」「PHPで普段とは違うものを動かしてみたい方」
